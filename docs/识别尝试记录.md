## 一、探针必须逐条验证的问题（任务书 4.1，Claude 未证实的 5 点）

| # | 问题 | 验证方式 | 结果 |
|---|---|---|---|
| 1 | 浏览器直连是否被 CORS 拒绝 | 探针 fetch 失败且无状态码即疑似 CORS | ✅ **通过**（2026-10-24 curl 实测：OPTIONS 预检与 POST 正式响应均带 `Access-Control-Allow-Origin: null`，file:// 放行；用户探针亦直连成功） |
| 2 | base64 是否要 `data:image/jpeg;base64,` 前缀 | 探针自动先试纯 base64、再试 data URL，显示哪种成功 | ✅ **有结论**（2026-10-24 用户实测）：纯 base64 → HTTP 400 拒绝；data URL（带 `data:image/…;base64,` 前缀）→ HTTP 200。**集成必须用 data URL 写法** |
| 3 | 公式返回是否 LaTeX、带不带 `$` 或 `\( \)` | 看 md_results 原文与 layout_details 的 formula 块 | ✅ **定论**（2026-10-24 用户回报原文）：行内 `$…$`、行间 `$$…$$`——与主应用 mathtext（$ 定界 + KaTeX）**直接兼容**，探针 renderRich 渲染未报错 |

**2026-10-24 探针层实测（ZCode 用 curl 做的，非用户数据）：**
- CORS 通过：预检与正式响应均回 `Access-Control-Allow-Origin: null`（file:// 的 null origin 被放行），Go 判据第 1 条不再是风险项；

- 用户随后**直连成功**，且探针用的是**裸 key（无 `Bearer ` 前缀）**——此写法实测可用。探针因此**未做任何修改**，保持已验证状态；
- 用户首次「两种写法都失败」的原因未定位（疑似密钥粘贴不全或网络瞬时问题），重试后消失，未复现；
- 用户首张照片（横拍）识别质量差，**疑似送入图像方向问题**（OCR 模型一般不自动纠正旋转），待用户按「原图（压缩后）」预览自查后重拍重测。

**2026-10-24 再续：四个悬项全部落定（用户口述，ZCode 转录）：**

## 三、Go / No-Go 判据（任务书 C3，现在写死，事后不得改）

**Go 需同时满足：**
1. 浏览器直连成功，没有 CORS 失败；
2. **5 张印刷体里至少 4 张**判定为「可直接用」或「改 1 处能用」（手写体单独统计汇报，不作为 Go 条件）；
3. 中位耗时 ≤8 秒；
4. 单张平均 tokens × 预计使用量（30 位用户 × 每人 20 张 = 600 张）不超过用户额度的 **50%**。算式：2255（印刷 5 张均值）× 600 ≈ **135 万** ≤ 额度 × 50%（用户口述额度「几千万」，按 2000 万计即 1000 万）→ **达标**（2026-10-24 测后填入；额度精确数待用户抄控制台）。

**任何一条不满足 = No-Go**：停止 C 部分，不集成；把本文件整理好（这就是报告里「尝试与局限」的素材），回到试用与修 bug。
时间盒：探针 ≤半天，集成 ≤1 天；**10-27 晚仍未稳定按 No-Go 冻结**。

## 五、安全声明与 C4 实现落地（2026-10-24 Go 当日集成）

- 密钥绝不写进 git 仓库，也不放进 GitHub Pages 的任何 js（已实现：`window.QT_OCR_KEY = null` 注入槽写在 index.html，仓库 / 线上 / zip 版恒为 null → 识别按钮自动隐藏）；
- **`make-dist.js --ocr-key-file <文件>` 已实现**：只把密钥注入本地单文件（dist/ 在 .gitignore）。用户出带识别功能单文件的命令：`node build/make-dist.js --ocr-key-file <key文件>`（key 文件放仓库外，用完删）；
- 前端里的密钥对拿到文件的人是可见的，混淆不算安全——专用账号、不充值、只用赠送额度；最坏情况额度用光，应用自动降级为纯拍照存图（识别失败只弹提示）；
- **C4 落地清单（本日）**：`js/ocr.js`（纯逻辑：请求体强制 data URL / 响应解析 / 额度护栏 / 错误文案）＋ `js/ui-ocr.js`（按钮 / 同意门 / 降级）＋ `ui-entry-photo` 接线（按钮位 + getBlobForOcr）＋ 构建注入。额度护栏 = 每设备每天 **30 次「成功」识别**（失败不计数）；同意门 = 首次点击明确告知照片会上传智谱服务器；识别结果只**追加**进题干、绝不覆盖，用户必须检查删改（识别可能有错）；
- **验证边界（诚实记录）**：Node 单测 25 项全过（全仓 282 项绿）＋ 无头 Edge 冒烟 7/7（按钮露出/隐藏、无照片降级、额度 30/30 拦截、全程无 JS 异常）；**应用内真实网络调用未在冒烟中覆盖**（同形 fetch 已由探针实测证明可用），待用户拿真 key 构建后真机点一次确认。
