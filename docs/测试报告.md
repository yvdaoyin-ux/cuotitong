## 三、统计模型测试明细（45 项）

### 3.1 数学工具正确性（6 项）

**为什么先测数学工具**：掌握度的可信区间依赖 Beta 分位数。若分位数实现有错，
上面所有结论都不可信。所以先用**有闭式解**的分布做独立对照 ——
这比硬编码常数更能发现实现错误。

| 用例 | 校验方式 |
|---|---|
| Beta(1,1) 中位数 0.5 | 均匀分布，解析解 |
| Beta(1,1) 的 2.5% 分位数 ≈ 0.025 | 解析解 |
| Beta(2,1) 分位数 = √p | 密度 2x → CDF = x²，闭式反解 |
| Beta(2,1) 的 95% 下界 ≈ 0.158 | 显式断言 `> 0`，说明为何不能用正态近似 |
| Beta(6,2) 自洽：CDF(中位数) ≈ 0.5 | 正向/反向互相验证 |
| 区间端点单调 low < mean < high | n = 1/3/10/50 |

> **开发中发现的真实错误**：最初我把 Beta(2,1) 的中位数写成 $1-1/\sqrt2 \approx 0.293$，
> 测试失败后才发现应当是 $\sqrt{0.5}\approx0.707$。**是测试纠正了我，不是我看代码发现的。**

### 3.2 掌握度（8 项）

| 用例 | 关键断言 |
|---|---|
| 零样本时掌握度 = 0.5 且数据不足 | 先验均值，`sufficient === false` |
| 全答对时严格递增且 < 1 | 30 次全对后为 0.9688 |
| 全答对收敛到 1 | 30 次后 > 0.95 |
| 全答错时严格递减且 > 0 | 对称性检验 |
| 区间随样本收窄 | 5 个采样点单调 |
| 4 次内数据不足，5 次起给结论 | 阈值边界 |
| 区间不越界 | low ≥ 0、high ≤ 1（正态近似会在此失败） |
| 平滑效果：答对 1 次 ≠ 100% | 断言 = 2/3 |

### 3.3 遗忘曲线（12 项）

| 用例 | 关键断言 |
|---|---|
| t=0 时 R=1 | 精确 1 |
| t 增大 R 严格递减且 > 0 | 扫 0→30 |
| S=1 时 1 天后 R = 1/e | 0.3679 |
| 稳定度越大忘得越慢 | 单调性 |
| 曲线在 t=S 处恰为 1/e | 定义自洽 |
| 稳定度递推对→×2、错→×0.5 | 1→2→4→2 |
| 连续答错不会低于 0.5 | 20 次全错后 = 0.5 |
| 大量答对指数增长 | 20 次后 = 2²⁰ |
| 优先级 = (1−R)×(1−掌握度) | 数值精确 |
| 优先级随掌握度升高而降低 | 方向性 |
| 优先级随遗忘加剧而升高 | 方向性 |
| kpState 汇总 3 对 2 错 = 4/7 | 端到端聚合 |

### 3.4 组卷抽样（10 项）

### 4.3 v1 → v2 迁移（12 项）

**这是最容易损坏用户已有数据的地方，所以测得最细。**

| 用例 | 关键断言 |
|---|---|
| 版本号升到 2 | `schemaVersion === 2` |
| 科目 id 被映射 | `calc→gaoshu`、`linalg→alglinalg` |
| 迁移后**无孤儿引用** | 遍历所有错题与作答的 kpIds，逐个断言知识点真实存在 |
| 同名知识点正确对应 | 旧「定积分」→ 新「定积分」且科目为 gaoshu |
| 改名走重命名表 | 「微分中值定理」→「微分中值定理与导数应用」 |
| 多对一自动去重 | 3 个旧知识点归到同一章后只剩 1 个 |
| 用户自建知识点保留 | `kp_uid_keepme` 原样 |
| 作答事件跟随错题 | `a.kpIds === m.kpIds` |
| 孤儿事件被清除 | 指向不存在错题的事件被删 |
| 迁移幂等 | 连跑两次结果深比较相等 |
| 无版本号数据也会迁移 | 删除 `schemaVersion` 后仍完成科目映射 |
| 迁移后仍能正常写入 | 新增错题成功，总数 = 5 |

> **开发中发现的真实缺陷**：最初 `normalize()` 在缺版本号时兜底成 `SCHEMA_VERSION`，
> 导致极早期数据被当作「已是最新」而**完全跳过迁移**，科目停在废弃的 `calc` 上。
> 单测「没有版本号的极早期数据也会被迁移」抓到了这个 bug。

## 六、开发过程中被测试抓到的真实缺陷

写这份报告时如实列出 —— **这些不是「为了显得严谨」而编的，是实际发生并被修正的**。

| # | 缺陷 | 怎么发现的 | 修正 |
|---|---|---|---|
| 1 | Beta(2,1) 中位数预期写错（0.293 vs 0.707） | 单测失败 | 改为用闭式解 √p 校验 |
| 2 | `normalize()` 提前写版本号，v1 数据**跳过迁移** | 单测「无版本号数据也会迁移」 | 缺版本号一律按 0 处理 |
| 3 | 迁移只处理错题，**自建知识点仍指向旧科目** | 单测「无孤儿引用」 | 知识点的 subject 也走映射 |
| 4 | 多旧知识点映射到同一新知识点产生重复 | 单测「多对一自动去重」 | 迁移后按 id 去重 |
| 5 | 重命名表把「微分方程」映射到「不定积分」等**错误章节** | 写测试时人工审阅发现 | 只保留等价映射，其余建同名知识点 |
| 6 | `QT.pages` 未初始化，所有页面注册失败 | **浏览器控制台报错**（单测发现不了） | 在 `util.js` 提前建好 |
| 7 | 主页把「数据不足」拼到 `<strong>` 外，样式错乱 | 读无障碍快照时发现 | 重写渲染逻辑 |
| 8 | 首页「待复习」用知识点数、复习队列用错题数，**口径不一致** | 人工核对两处代码 | 统一只认 `buildReviewQueue` |
| 9 | 用户写的解法**没有保存**，交卷即丢 | 实际走流程时想到要验 | `recordAnswer` 增加 `note` 参数 |
| 10 | 结果页对样本不足的知识点只显示「数据不足」，用户看不到任何数字 | 实测结果页 | 显示数值 + 标注「仅供参考」 |
| 11 | 文档里 `n=5` 的区间宽度写了 0.6594（**编造值**） | 写完后回头核验 | 实测为 0.5324，已改正 |
| 12 | 文档表格把「答对 n 次/答错 n 次」误当总样本量 | 逐行核验 | 全部按实测值重写 |

> **第 6、7 条说明**：单元测试覆盖不到 DOM 注册与渲染拼接，
> 必须真的在浏览器里打开、读控制台和无障碍树。这也是为什么本报告单列「浏览器端实测」一节。
