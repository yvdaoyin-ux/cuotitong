## 四、请你重点验的四件事

### 4.1 Beta 分位数实现的数值正确性（最该查）

我用的是**精确分位数**（连分式求逆 + 二分），不是正态近似——因为正态近似在 α、β 很小时会给**负的下界**。

我没有 R/SciPy 环境，只用有闭式解的分布自证过：Beta(1,1)（均匀）、Beta(2,1)（CDF=x²，分位数=√p）。

**请帮我交叉验证这几组**（我的实现输出）：

```
qbeta(p=0.025, a=4, b=3) = 0.2227780955     ← 例：答对3错2 的 95% 区间下界
qbeta(p=0.975, a=4, b=3) = 0.8818827512
qbeta(p=0.025, a=6, b=1) = 0.5407418736     ← "5次全对"的区间下界，minSamples 的依据
qbeta(p=0.5,   a=2, b=1) = 0.7071067812     ← 应为 √0.5 = 0.7071067811865476
qbeta(p=0.025, a=1, b=2) = 0.0125791171
qbeta(p=0.975, a=1, b=2) = 0.8418861170
```

若有偏差，请指出是哪一组、差多少。

### 4.2 `minSamples = 5` 的依据

我的推理：**Beta(6,1) 的 2.5% 分位数首次超过 0.5**，即「连续答对 5 次后，才有 97.5% 把握认为真实正确率 > 50%」。

实测确认了这个转折点（n=4 时下限 0.4782，n=5 时 0.5407）。

**但这是我的推理，不是文献依据。** 你认为这个口径站得住吗？还是该用别的（比如区间宽度阈值、或按知识点难度分级先验）？

### 4.3 双写/事件溯源这个设计

我删掉了任务书要求的「掌握度」存储，改为事件溯源。请判断：
- 这在报告里该怎么表述才不算「没按任务书做」？
- 是否存在我没想到的隐患（比如数据量大到几千条时重算的开销）？

### 4.4 「+ε 加权无放回 + 40% 配额」是否真能保证多样性

我的实现：配额 cap = ⌈总题数 × 0.4⌉，凑不满时**逐级放宽**（最多放宽两级），否则返回不足数目。

测试用 200 次抽样验证了「同一知识点不超过 4/10」。但**放宽机制会不会破坏「≤40%」的承诺**？请你看逻辑。
