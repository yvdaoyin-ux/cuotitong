## 一、验证过程时间线（每一步都实测，含两次失败）

### 1.1 探针首测失败（「两种写法都失败」）→ 已定位闭环

用户第一次跑探针，raw 和 data URL 两种写法都失败。当时我（ZCode）用 **假 key**（不碰用户真 key）做了两组 curl 诊断：

| 测试 | 结果 | 结论 |
|---|---|---|
| `OPTIONS` 预检（Origin: null） | 200，带 `Access-Control-Allow-Origin: null` / `Allow-Methods: POST` / `Allow-Headers: authorization, content-type` | **file:// 的 null origin 被放行**——判据 #1 从「未验证的风险项」变成「实测通过」 |
| `POST`（假 key，带 Origin: null） | 401 `{"error":{"code":"1000","message":"身份验证失败。"}}`，且正式响应也带 ACAO | 接口活着、CORS 全链路通、错误 body 可解析 |

后经用户确认：**首测失败原因是当时 API key 贴错了**（第 4 点用户原话「我当时都失败是因为我api搞错了」）。方案、探针、接口都无责任。此教训已写成流程事实：**拿到「请求失败」先区分网络层/鉴权层/参数层，别急着改方案**。

### 1.2 第二测：手写体首张，质量超预期

用户按四要点重拍（单题、文字正、拍满画面、光匀）后：

- `file=raw`（纯 base64，158KB 请求体）→ **HTTP 400**；`file=dataurl` → **HTTP 200、2055ms、usage 1699 tokens**（prompt 1004 / completion 695）
- 用户判定「识别的不错，直接用没问题」——**而这张是手写体**
- 由此定论两个接口事实：**① `file` 必须是 data URL，纯 base64 一律 400**（任务书未验证点 #2 闭环）；② **裸 key（无 `Bearer ` 前缀）实测可用**——探针因此一行未改（已验证能跑的工具不动）

另有一个插曲：用户更早一张**横拍**照片识别「一塌糊涂，只认出竖着的手机水印」——定位为**照片本身文字方向不对**（OCR 模型不自动纠旋转，横倒的文字里只有水印可读）。这条教训写进了给用户的拍摄四要点，也影响了集成文案（识别失败提示「试试拍得近一点、文字摆正」）。

### 1.3 五张印刷体：判据 #2 的正戏

用户连测 5 张印刷体（教材页），全部 `raw`→400、`dataurl`→200：

| # | 耗时 ms | tokens | 用户判定 |
|---|---|---|---|
| 1 | 828 | 2562 | 可直接用 |
| 2 | 852 | 1976 | 可直接用 |
| 3 | 1672 | 2951 | 可直接用 |
| 4 | 982 | 1737 | 可直接用 |
| 5 | 9282 | 2048 | 可直接用 |

- **中位 982ms**（判据线 ≤8s；9.3s 是离群值）；tokens 均值 **2255**
- 用户回报了一段 md_results 原文（教材「隐函数组/反函数组」页）：**公式全部是 `$…$` / `$$…$$`**——与主应用 mathtext 渲染器（$ 定界 + KaTeX）**同一种语言，直接兼容**（任务书未验证点 #3 闭环，这是最好的可能答案）
- 诚实评价那段原文：矩阵、行列式、偏导都正确输出了 LaTeX，**但有识别错误**（如「解设 $F=uf$」一行错误、方程组两式间丢逗号、末段错字）——这正是集成时坚持「结果只追加、必须用户检查删改」的依据

## 三、C4 集成设计与决策理由

### 3.1 文件分工

| 文件 | 职责 | 行数 |
|---|---|---|
| `js/ocr.js` | **纯逻辑**（Node 可测）：buildRequestBody / parseResponseText / quotaCheck / quotaRecord / friendlyError | ~130 |
| `js/ui-ocr.js` | **浏览器层**：按钮绑定 / 同意门 / 额度读写 / fetch+30s 超时 / 结果插入 / 降级提示 | ~180 |
| `js/ui-entry-photo.js` | 仅 3 处小改：按钮槽位（默认 hidden）、attach 里 `QT.uiOcr.bind(el)` 钩子、`getBlobForOcr()`（先新拍池后已入库旧图） | 340→357 |
| `build/make-dist.js` | 新增 `--ocr-key-file <文件>`：读文件→trim→长度≥16 校验→替换注入槽 | +25 |

**ui-entry.js 保持 499 行未动**（500 行硬上限仍在）。

### 3.2 实测事实直接编码进代码（不留犯错空间）

- `buildRequestBody` **直接拒绝非 data URL 输入**并抛错——400 的教训变成类型约束，调用方不可能再发纯 base64；
- 定论之后**不再重试两种写法**（探针时代需要探索，集成后只有一个正确姿势，省一半请求）；
- `Authorization` 用**裸 key 无 Bearer**（探针实测可用；没测过 Bearer 就不写没测过的写法）；
- `parseResponseText` 的判定顺序：先解析 JSON → 有 `error` 字段透出服务端 code/message（比「HTTP 401」有用，实测过假 key 返回）→ 非 JSON 判 BAD_JSON → 非全 2xx 判 HTTP_xxx → 成功时兼容顶层与 `data` 包一层。

### 3.3 密钥安全模型（任务书第五节声明的落地）

```
index.html（仓库/线上/zip）: window.QT_OCR_KEY = null;  ← 注入槽，恒 committed 为 null
                              ↓ make-dist.js --ocr-key-file 只在本地单文件构建时替换
dist/错题通-单文件.html:     window.QT_OCR_KEY = "<key>";  ← dist/ 在 .gitignore，不进 git
```

- 仓库、GitHub Pages、离线 zip 三条渠道**永远没有密钥**，`ui-ocr` 见 null → 按钮整个隐藏（冒烟实测第 6 项）；
- 密钥对拿到单文件的人可见（混淆不算安全）——安全模型 = 专用账号 + 不充值 + 只用赠送额度 + 护栏；最坏情况额度用光，自动退化为纯拍照存图；
- 验证过：无 key 构建槽位保持 null（grep 计数 1）；假 key（`test-fake-key-…`，放 /tmp，用完删）注入生效；**真 key 从未经过我手**。

### 3.4 隐私与护栏

- **同意门**：第一次点按钮弹 confirm，文案诚实——「当前照片会发送到智谱开放平台的服务器完成识别，智谱如何处理该图片以其隐私政策为准；应用本身不会在本地之外另存副本」，同意后 localStorage 记住（`qt:ocrConsent`）；
- **额度护栏**：每设备每天 **30 次「成功」识别**（`qt:ocr`，跨天自动重置）。选「成功才计数」的理由：失败请求（400/401/超时）本就不消耗服务端 tokens，成功请求才耗——**计数口径与真实消耗一一对应**，对用户温和、对额度照样保守；
- **照片区 hint 文案**随有无 key 切换：无识别功能时保持「只存在本机，不会上传」；有识别功能时改为「点『识别文字』才会上传当前照片到智谱服务器识别（每日限 30 次）」——**隐私声明不再说满**。

### 3.5 降级矩阵（OCR 任何失败都不影响录题）

| 场景 | 行为 |
|---|---|
| 无密钥版本 | 按钮不渲染（不是禁用，是 hidden），功能等于不存在 |
| 没拍照片就点 | toast「先拍一张照片，再点识别。」，零网络请求 |
| 当日 30 次已满 | toast「今日 30 次识别额度已用完」，零网络请求 |
| 网络断/请求异常 | toast 网络失败原因 +「照片仍在，不影响录题」 |
| 30 秒超时 | AbortController 中止，toast「识别超时」 |
| 服务端 4xx/5xx | 透出 code+message（1000 → 「密钥无效或格式不对」） |
| 200 但 md_results 空 | toast「没识别出文字。试试拍得近一点、文字摆正。」（**仍计数**——这次请求真实消耗了 tokens） |
| 成功 | 结果**只追加**进题干（`cur.replace(/\s*$/,'\n') + md`），派发 input 事件刷新公式预览，toast 提醒「识别可能有错，请检查删改」 |

### 3.6 与任务书的偏离（3 处，均记录）

1. **护栏计「成功」次数**（任务书只说 30 次/天，未说口径）——理由见 3.4；
2. **识别结果整体追加进题干**，不做二次编辑弹窗——C4 是「最小集成」，编辑能力题干本身就有；
3. **OCR 不进埋点/匿名导出**（entry_open/entry_save 与 export-usage 未动）——任务书 C4 清单没要求；但见第六节待决问题 1，试用数据回收可能需要。
