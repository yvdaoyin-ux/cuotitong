## 一、做了什么

新增 4 个文件（全部 ≤400 行）+ 修改 9 个。schemaVersion 未动（v3 的 `imageIds` 字段阶段 1 已就位，本轮只是真正用上它）。

### 1. js/image-pipeline.js（192 行）—— 压缩管线

- **纯函数**（Node 可测）：`computeTargetSize`（长边 ≤1280、只缩不放、取整后不小于 1px、非法入参返回 null）、`qualitySequence`（默认 [0.72, 0.61, 0.5] 逐档降，下限 0.5 必含）、`overSize`（恰好 200KB 不算超）、`base64SizeOf`（含图备份预估值）
- **浏览器函数** `compressFile(file)`：`createImageBitmap(file, {imageOrientation:'from-image'})` 优先处理 EXIF 朝向，不支持时退化 `<img>` + objectURL + canvas；JPEG 白底填充（防透明区域变黑）；逐档质量尝试，≤200KB 即停，到 0.5 档无论多大都用它

### 2. js/image-store.js（214 行）—— 存储层

- IndexedDB 库 `qt-images`、store `images`：`{ id, qid, blob, w, h, size, createdAt }`。**存 Blob 不存 base64，绝不碰 localStorage**（比任务书多存一个 `size` 字节字段，占用统计用）
- `ImageStore` 接口：**内存实现（Node 测试）+ IndexedDB 实现，全部方法返回 Promise，同一契约**，测试可注入假 factory
- `openImageStore()`：打不开（隐私模式 / file:// 受限 / 4 秒超时 / onblocked）一律 **resolve null，绝不 reject**——由 UI 降级，**绝不悄悄退回内存存储**（那样图片刷新即丢，用户会以为存上了）
- `cleanupOrphans(store, liveQids)`：孤儿清理只走 `qid` 索引的键游标（key=qid、primaryKey=id），**全程不把 blob 载入内存**

### 3. js/image-view.js（266 行）—— 展示层

- `urlFor(blob)` 统一创建并登记 objectURL，页面 `dispose()` 时 `revokeAll()`（任务书 3.3 的释放要求）
- `hydrate(root)`：把渲染时留下的 `data-img-ids` 占位盒异步灌成缩略图（渲染是同步的、取图是异步的，所以只能先占位后灌水）
- 全屏查看器：黑底覆盖层 + 双指捏合缩放（`touch-action:none` + JS transform，1–5 倍）+ 双击 1x/2x + 滚轮（调试用）+ 多图左右切换 + 底部操作按钮位。**不引库**

### 4. js/ui-entry-photo.js（340 行）—— 录题页拍照卡

- 极速模式下**拍照卡是第一个卡片**（首选路径）；两个按钮 `拍照`（`capture="environment"`）/`相册`；**每题最多 3 张**
- 拍完立即原位显示缩略图（压缩同步完成后逐张出现）；点缩略图进全屏查看器，操作按钮「重拍这张 / 删除这张」；缩略图角上有 ✕ 快捷删除
- **只拍照不填字可保存**：临时图的 id（`uid('img')`）在拍照时就写进 `draft.imageIds`，保存校验里「图片」即算内容
- 保存时 `saveFor(qid)`：待提交池写入 IndexedDB（qid 落到真实错题 id）；**个别图存失败（配额满）时把失败 id 从错题记录里摘掉**，不留指向不存在图片的 imageId
- 「保存并继续」：照片池清空（与文本字段同待遇），科目/知识点/错因保留，焦点回来源框
- 编辑态：旧图从库里异步加载显示；删除旧图只是**标记**，点保存才真正删（不保存可反悔）
- 降级：图片库就绪前按钮禁用；确认不可用后隐藏按钮区，显示「当前环境不支持保存图片，请用文字或来源录题」

### 5. 周边接入

- **列表页**：每题首图 96px 缩略图；**组卷作答页**：题干空显示来源行「📄 来源（题干见图片/原文）」；**打印页**：图片 `break-inside: avoid`、`max-width:100%`
- **删除错题**：即时连带删图（孤儿清理兜底异常退出场景）
- **设置页**：图片占用统计（`navigator.storage.estimate`，>100MB 红字）；**含图片备份**勾选框（base64 附在 `images` 数组，**>20MB 先弹确认**，默认不含图）；导入自动识别两种格式（先摘出 `images` 再走 `importJson`，**不让图片数据混进业务数据**）；「清空全部数据」连带清图
- **app.js 启动**：图片库初始化（不阻塞主界面）+ `navigator.storage.persist()`（失败静默）+ 孤儿清理

## 六、本次踩到的坑（已写进 PROJECT_STATE）

1. **`openKeyCursor` 的 key 语义**：在对象存储上开游标 key=**主键**，在索引上才是 key=**索引键**。`listQidPairs` 第一版直接在 store 上开游标，qid 全是 undefined——孤儿清理会把**所有图**误判为孤儿（这是会删光用户图片的事故级 bug）。开发中自查发现，改为走 `qid` 索引。
2. **待提交图片忘记建 objectURL**：初版 `url:null`，缩略图永远显示「…」。合成图实测当场暴露。
3. **`reset()` 把 store/页面引用一并置空**：「保存并继续」后照片卡会失灵。拆成 `reset()`（清照片池，页面继续用）与 `dispose()`（离开页面）。
4. **Windows 无头 Edge 两个坑**：①`--dump-dom` 的 stdout 被丢弃（GUI 子系统），拿到 0 字节文件，必须起 `--remote-debugging-port` 走 CDP 读结果；②`--headless`（旧模式）会打开 Edge 同步欢迎页丢掉命令行 URL，必须 `--headless=new`（与 PROJECT_STATE 既有条目「必须加 --user-data-dir」叠加使用）。
5. **测试框架 `group()` 忘了调用回调**：队列里只有组名没有用例，「0 项 0 失败」假绿。教训：**测试项数必须与预期对账**——对账时还发现汇报初稿把 image 套件分项写成「15+11」（合计 38≠36），实为 14+10，已在 `docs/阶段3完成汇报.md` 更正。
